# Гори та Степ · шрифтова майстерня

Монорепозиторій для розробки шрифтів конскрипту **«Гори та Степ»** — фонетичної
абугіди для української мови — та потенційно інших гарнітур.

**🌐 Сайт-презентація:** <https://hory-ta-step.github.io/> —
живе демо шрифтів у браузері, всі правила письма, цифри-колосся, пунктуація
степу і завантаження TTF. Там-таки [інтерактивний довідник](https://hory-ta-step.github.io/interactive.html)
із транслітератором і вертикальним режимом «Гори». Сайт збирає й публікує
GitHub Actions (`.github/workflows/pages.yml`) на кожен push у `main`.

Знак не малює літеру, а кодує звук: пряме стебло з засічкою — проривні,
хвилясте — протяжні, дуга праворуч — губні, ліворуч — зубні, замкнена дуга —
дзвінкі, петля крізь стебло — задньоязикові, вільний розчерк — плавні.

## Швидкий старт

```bash
git clone https://github.com/hory-ta-step/hory-ta-step.github.io.git
cd hory-ta-step-fonts
make setup      # один раз: створює .venv і ставить залежності
make            # build + test + preview
```

Готові шрифти з'являються у `fonts/`, зразки — у `docs/preview-*.png`.
Докладніше про локальну роботу — у [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

| Ціль | Що робить |
|---|---|
| `make setup` | створює `.venv` і встановлює залежності |
| `make build` | збирає всі гарнітури з `sources/` у `fonts/*.ttf` |
| `make test` | smoke-тести: покриття абетки, лігатури, метрики, контури |
| `make preview` | рендерить зразки текстів у `docs/` |
| `make clean` | прибирає артефакти |

## Як це працює

```
sources/<гарнітура>/glyphs.json   контури штрихами (SVG-шляхи M L H V Q)
sources/<гарнітура>/family.json   метадані: назви, метрики, стилі
        │
        ▼  tools/build.py + tools/stroker.py
штрих → семплінг Безьє → офсетний полігон (round/butt капи) → TTGlyphPen
        │
        ▼  fontTools.fontBuilder + feaLib (liga: дж/дз; calt+mark: абугіда)
fonts/HoryTaStep-<Стиль>.ttf
```

Гліфи описуються *штрихами* — так само, як на інтерактивній сторінці
скрипту, — а не готовими контурами. Товщина, капи і геометрія стилю
(друкований/рукописний) задаються в `family.json`, тож одна зміна контуру
в `glyphs.json` оновлює всі накреслення.

## Стилі

- **Drukovanyi** — друковане накреслення: прямі стебла з засічками,
  правильні дуги, обрубані капи.
- **Rukopysnyi** — рукописне: розчерки-ніжки, каліграфічні дуги,
  заокруглені капи.
- **Karbovanyi** — рубане: самі прямі лінії, без жодної дуги — письмо,
  карбоване сокирою на дереві чи камені, як давні карби-зарубки.
- **DrukovanyiZhyrnyi / RukopysnyiZhyrnyi** — жирні (OS/2 weight 700):
  товщий штрих, а тісні знаки (м, н, ж, ш, щ, ґ, г, дж, дз) мають
  компенсовані контури — чаші розведені, петлі ширші, щоб не злипалось
  (частковий набір `*-bold` у `glyphs.json` поверх базового).

Великі й малі літери мапляться на ті самі гліфи (унікейс).
`д+ж` і `д+з` замінюються лігатурами через OpenType `liga`.

Цифри — степова лічба колоссям: `0` — зерно-коло, `1`–`4` — стебло,
на якому зерна чергуються праворуч і ліворуч, `5` — повний колос зі
схиленою верхівкою, `6`–`9` — схилений колос із зернами.

Пунктуація — знаки степу, а не запозичені форми: крапка — зерно, що
впало в землю; кома — стеблинка, зігнута вітром; оклик — блискавка
над степом; питання — вихор, що здіймає пил; дефіс — місток; коротке
тире — обрій, довге — обрій із курганом на видноколі; трикрапка —
посів, три зерна по діагоналі; лапки — крила вітру; дужки — схили
гори; апостроф — вітерець.

Письмо поводиться як справжня абугіда: голосна після приголосного
стає zero-width маркою і сідає над ним (`calt` + `mark`), м'якість —
маркою під ним; на початку слова голосна лишається окремим знаком
на кургані. Йотовані `я ю є` після приголосного розпадаються на
вітер + голосну («ля» = л + завиток унизу + а вгорі); на початку
слова, після голосної, `й`, `ь` чи апострофа — листок-`й` зі знаком
угорі. `ї` — завжди й+і. Потрібен шейпер із підтримкою OpenType (HarfBuzz,
CoreText, DirectWrite — тобто всі сучасні браузери й редактори).

## Додати нову гарнітуру

1. Створіть `sources/<назва>/` з `family.json` та `glyphs.json`
   (за зразком `sources/hory-ta-step/`).
2. `make` — збирання, тести і зразки підхоплять її автоматично.
3. CI на GitHub зробить те саме на кожен push, а на тег `v*` —
   прикріпить .ttf до релізу.

## Реліз

```bash
git tag v0.2 && git push --tags
```

GitHub Actions збере шрифти, прожене тести і опублікує реліз із .ttf.
